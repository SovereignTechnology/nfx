# Documentation map

This directory holds the decision records, the project status log and the reference
copies behind NFX, the Nostr-identified, peer-seeded video network specified in
[`spec/`](../spec/README.md). Every area below carries one label, so you can tell what
to rely on. Labels and statuses are as of 2026-10-12.

## Where to start

1. [`README.md`](../README.md): what NFX is, and how to build and run it.
2. [`spec/README.md`](../spec/README.md): the NFX-01..12 reading order with each
   document's status and freeze milestone, the status model and conformance levels.
3. [`nfx/status.md`](nfx/status.md): the resume point and status log. Work picks up
   there.
4. [ADR 0008](decisions/0008-multi-network-master-plan.md): the master plan, with the
   milestones (section 5) and how this repository relates to the demo (sections 1 and 3).

## Labels

- **Living**: kept current as work proceeds.
- **Spec**: a protocol document in `spec/`. Its status (Frozen, Draft or Living), freeze
  milestone and freeze date are in the table in [`spec/README.md`](../spec/README.md),
  which is authoritative; this index does not repeat them.
- **Record**: point-in-time; do not rewrite.
- **Superseded record**: some statements were overtaken by later work; the notes below
  the table say which, and by what.
- **Vendored**: an upstream copy.
- **Demo**: mirrored read-only from the demo repository.

### Statements overtaken since the records were written

- **`nfx/nfx-10-m1-plan.md`**: its header says the work is built on branch
  `nfx10/mesh`, which no longer exists; the work is in `main`. Part C recommends
  deferring the bridge seeder to M2. The decision in the same file reversed that, and
  the bridge shipped in M1 (`nfxd run --bridge`;
  see `nfx/reviews/2026-09-24-nfx10-m1.md`).
- **`nfx/freeze-m1-candidate.md`**: its "What freezing does", "mechanical step" and
  "Recommendation" text is written before the freeze, which happened on 2026-09-24
  (`spec/README.md`). It says `nfxd` does not join swarms yet; `nfxd run --gossip` now
  does (`nfx/reviews/2026-09-24-hardening.md`). It counts 13 vector files; there are 14.
- **ADR 0002** is the history of the v0 stack; ADR 0006 supersedes it as forward-looking
  architecture. **ADR 0005**'s Q1 split rule was superseded in part by ADR 0007 (minimum
  PAY size, creator carry).

## Root file read by the demo

Two demo tests read `SECURITY.md`, both in `packages/core/src/payment/__tests__/`:

- `threat-table.test.ts` reads the T1-T16 threat table, including the wording of row
  T13.
- `invariants.test.ts` reads the eight numbered money-path invariants between the
  headings "Non-negotiable invariants" and "Locked directories", and the phrase "holds
  NIP-60 state in memory only".

Keep the threat table and the invariants section intact. If a merge of `demo/main`
conflicts in a root file, resolve it by hand.

## The add-only rule

Demo mirror paths are never edited here; new work goes in `spec/`, `crates/`, `web/`
and `docs/nfx/` (ADR 0008, section 3; `crates/ci/check.sh` has a step that checks it).
