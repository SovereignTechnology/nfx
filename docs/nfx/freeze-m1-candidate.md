# M1 freeze candidate: NFX-02 to NFX-06 (2026-09-24)

**Status: candidate, not frozen.** Freezing is sovtech's call. This page shows what a
freeze would lock, what changed to get here, and the one decision still open.

## What freezing does

Per `spec/README.md`:
- NFX-02, 03, 04, 05 and 06 become **Frozen@M1**: normative for M1 implementations.
- From then on, a behaviour change needs a `specver` bump (NFX-01 §4) and a new namespace
  (`nfx:<network>:2`), never an edit in place. Typos and clarifications that change no
  behaviour may still be fixed in place, with a changelog line.
- NFX-11 records the freeze and the pins it depends on.

The mechanical step, once decided:
- each document's status line becomes `Frozen (M1) · <date>`;
- the README table moves from "Draft" to "**Frozen**";
- NFX-11's changelog gets the freeze entry.

## What this candidate changed

Everything below is on `main` after this work, and every item has a test.

| Area | Change | Evidence |
|---|---|---|
| **Tickets (NFX-06 §2, NFX-11 §4)** | The ticket string form is now stated byte for byte: variant, endpoint id, relay, direct addresses, format, hash, then `"blob"` plus lowercase unpadded base32. So is the collection hash: BLAKE3 of the concatenated member BLAKE3 hashes. It was "pin at M1" with placeholders in the vectors. | New `tickets.json`. The Python generator encodes the tickets from the documented layout without iroh. The Rust test decodes them with iroh-blobs 0.103, compares every field, and re-encodes byte for byte. `Node::seed` of the vector video yields exactly the pinned collection hashes. |
| **Ticket ↔ `node` (NFX-06 §2)** | Every ticket's endpoint id MUST equal the beacon endpoint's `node`, and a watcher ignores an endpoint whose tickets name another node. | `SwarmPull::learn` enforces it (origin test: a "borrowed" beacon is ignored). |
| **Beacon vector (NFX-03)** | Real tickets, and a real ed25519 iroh endpoint id (the old one was a sha256, which no ticket can carry). | `beacon.json`, `beacon-invalid.json` and `gossip.json` regenerated. The Rust and WASM vector tests pass. |
| **Schemas (NFX-03 §4, NFX-05 §2)** | The "normative" JSON schemas are now checked against the vectors in CI. The schema must accept every valid vector, reject exactly the structural invalid cases, and pass the cross-reference ones, which only a parser can see. | `spec/schemas/check.py`, a step in `check.sh`. |
| **Gossip (NFX-06 §4)** | The 4 KiB envelope limit is enforced before parsing. It had been stated but never checked. | Vector test at 4096 bytes (accepted) and 4097 (refused). |
| **Clarifications** | `alt` length is a publisher SHOULD. Beacons carry no extra tags, and readers ignore unknown ones. AAC-LC is required only when the source has audio. Hash-addressed URLs carry no query string. "Endpoint id" replaces "NodeId". Collection order comes from the playlist alone. | Spec text and changelogs. Each one records behaviour the code already had, or removes an ambiguity. |

Earlier amendments, in the documents since 2026-09-23 and part of what would freeze:
- NFX-02 §4, current revision with a 15-minute horizon;
- NFX-04 §2, `created_at` bound;
- NFX-05 §3, every `URI` attribute counts, plus the `duplicate-uri-attribute` vector;

## Conformance evidence

- **Vectors:** 13 files, regenerated byte for byte (`generate.py --verify`), with schemas
  checked (`check.py`).
- **Implementations:**
  - `nfx-proto`, native Rust and the same code as WASM;
  - `nfx-node`, `nfxd` and the test player;
  - independent Python encoders in the generator: canonical JSON, BIP-340, tickets and
    collections.
- **Interop:** the Phase A exit run
  ([`phase-a-exit.md`](phase-a-exit.md)).
  - Two hosts, a real iroh relay, a direct path and a real browser.
  - The browser resolves by manifest address over Nostr and plays from a beacon-named
    origin.
- **Not yet:** a second, independent full implementation (the README's "Stable" bar).
  That is not needed for a freeze.

## Open decision (blocks the freeze)

**NIP-09 deletion collides with scoped-relay admission.**
- NFX-02 §6 says a creator may delete a manifest with a NIP-09 request, and seeders MUST
  stop beaconing a deleted manifest.
- NFX-04 §1 has scoped relays refuse every kind except 38504 and 20464. A kind-5
  deletion therefore never reaches them, and seeders listening there never learn of it.
- Nothing implements the seeder side today either.

Options:
1. **Admit targeted deletions (recommended).** Scoped relays accept a kind-5 event
   only when every `a`/`e` it names is a kind-38504 manifest of the same author in a
   served namespace. They apply it to stored manifests and forward it. Readers and
   seeders honour it: `Relays::manifests` drops deleted revisions, and `nfxd` stops
   beaconing. This needs NFX-04 §1 and §2 text (a rate limit for kind 5), a vector, and
   code in the relay, the reader and the daemon.
2. **Drop NIP-09 from NFX-02.** Withdrawal would then be the renunciation manifest only.
   But that still leaves the video playable (open, price 0), so there would be no real
   "withdraw". Simpler, weaker.
3. **Defer:** freeze with §6 reworded to "SHOULD, where the reader can see NIP-09
   events", and solve deletion at a later specver. This leaves a known gap in a frozen
   document.

## Not blocking (SHOULD-level, not implemented)

- NFX-04 §1: NIP-42 authentication for publishing (and the relaxed authenticated beacon
  floor).
- NFX-04 §6: relay self-announcement (NIP-66 kind 30166). It is an operator step, and
  `nfxd` does not publish one.
- NFX-06 §4: gossip is implemented in `nfx-node`, but `nfxd` does not join swarms yet.
  Nostr beacons carry discovery.

These are conformant omissions: a SHOULD, or an optional feature.

## Recommendation

1. Decide the deletion question. Option 1 is roughly a day of work.
2. Freeze NFX-02 to 06 at M1 once it is in.

Everything else in this candidate is ready.
