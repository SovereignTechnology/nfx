# NFX 0.1.0

The first release of NFX: the headless node `nfxd` and the packager `nfx-package`, prebuilt for
linux-x64, beside the source. NFX is a Nostr-identified, peer-seeded video network; this release
covers **free** video end to end. Payments are specified (NFX-07) but not in it.

## What is in it

- **`nfxd`**: `key`, `publish`, `delete` and `run`. `run` seeds (`--seed`), fetches (`--fetch`) and
  serves a pull-through origin (`--pull`, `--origin`) over iroh (NFX-06), every file checked
  against the signed hash list; it can embed a scoped Nostr relay (`--embed-relay`, NFX-04) and
  the browser-mesh tracker (`--embed-tracker`, NFX-10), and order the seeders it pulls from by
  seeder ratings (NFX-16, read-only). `--iroh-relay-ca` trusts a private CA for a network's own
  iroh relays.
- **`nfx-package`**: NFX-05 packaging from any video ffmpeg reads: the rendition ladder, CMAF
  output, the hash list and the manifest draft. It needs `ffmpeg` and `ffprobe`.
- **The specification**, NFX-01 to NFX-06 Frozen (M1), the rest Draft (`spec/README.md`).
- **From source only:** the Tauri desktop viewer (`crates/desktop`) and the browser test player
  (`web/player`).

## Tested with nutflix-pear

The nutflix-pear desktop app (0.1.1) speaks NFX over iroh through a helper (ADR 0103). Both
directions are tested in nutflix-pear's CI against `nfxd` built from this tree:

- **The exit run** (`nfx-exit.yml`): `nfxd` seeds and nutflix-pear lists the video, finds the
  seeder by its live beacon and plays every rendition, byte for byte; nutflix-pear packages a video
  the way its Studio does and seeds it, and `nfxd` fetches it, verifies every file, seeds it and
  serves it. ffmpeg decodes both.
- **The NAT matrix** (`spike-iroh.yml`): `nfxd` and the nutflix-pear helper, each way, behind open,
  consistent and symmetric NATs, over a plain and a TLS iroh relay: 33 of 33 judged cells pass,
  and behind consistent NATs with a TLS relay's address discovery the two implementations
  holepunch and go direct.

## What it does not do

- **No public network.** There is no public scoped relay or iroh relay for `nfx:testnet:1` yet:
  run your own (`nfxd run --embed-relay … --iroh-relay …`) and point your peers at them.
- **No payments.** The money crates (`crates/nfx-pay`, `crates/nfx-pay-wire`) are locked and not
  deployed; every video served is free.
- **Linux x64 binaries only**, not signed by an operating-system vendor. The Hypercore profile
  (NFX-12) is not implemented in Rust.
- **Fetch throughput:** in the NAT matrix `nfxd` fetched at 17–26 Mbit/s where the nutflix-pear
  helper reached 420–500, on the same links. That is above what a 720p stream needs, and open.

## Verify

`sha256sum -c SHA256SUMS` checks that the tarball is intact; it does not say who made it. For that,
the release carries `release-event.json`: a Nostr release notice (kind 30071, `d` = `nfx`) signed
by the SovTech key `npub1s0vtechh66tx7vrwdud8zfyheu9zca7swwfrzd4qu2a4f93mxs6qvn9adx`, listing the
tarball's sha256 and size; the same notice is on Nostr relays. To check it, with Node 22.18 or
newer and a checkout of nutflix-pear (whose release scripts sign and verify both projects'
notices):

```sh
git clone https://github.com/SovereignTechnology/nutflix-pear.git && cd nutflix-pear
npm ci --ignore-scripts
node scripts/release-verify.mjs release-event.json --d nfx nfx-0.1.0-linux-x64.tar.gz
```

It checks the signature, that the key is SovTech's, that the notice is NFX's, and the file's size
and sha256. The release is built by `.github/workflows/release.yml` from the tagged commit in the
pinned `rust:1.98.0-bookworm` image, `--locked`, with the commit's timestamp and the build paths
remapped.
