# NFX 0.1.1

A small release: the scoped relay inside `nfxd` now answers a search from a video's title as well as
its description. Everything else is as in [0.1.0](v0.1.0.md): `nfxd` and `nfx-package`, prebuilt for
linux-x64, beside the source; free video only.

## What changed

- **A NIP-50 search matches a manifest's title** (#26). The relay's in-memory store matched a
  search against an event's content only, and a manifest's content is its optional description, so
  a video published without one was in the relay and invisible to the nutflix-pear app's search,
  which is how that app finds NFX videos (its Trending and Shorts feeds never list them). A search
  is now a case-insensitive substring of the content **or** of the `title` tag, the way
  nutflix-pear's own test relay matches. `limit` applies after the match, newest first; a blank
  search is no search; nothing outside the namespace or the other filters is ever returned. NIP-11
  lists 50 beside 1, 11 and 40 (NFX-04 §3 requires 11 and 40 to be included).
- **The crates are 0.1.1** (`nfxd`, `nfx-node`, `nfx-media`), and `nostr-database` is now a direct
  dependency of `nfx-node`, at the version `nostr-sdk` already locks.

## Tested

- `nfx-node`'s 34 tests pass, including one that searches by a title with no description, by a
  description word, in either case, with a limit and with no search, and a unit test that a search
  never widens a kind, author or time constraint. Clippy is clean at `-D warnings`, and
  `cargo deny` passes with the new dependency.
- A search over a full 20,000-event store costs about what an unlimited kind query already does
  (measured: 56 ms against 62 ms; the old store search took 39 ms).
- **The data path is unchanged from 0.1.0**, which the nutflix-pear desktop app (0.1.1) plays on two
  machines over a tailnet, with `nfxd` as the seeder (checked by a person pressing play).
  This release changes the relay's search only: iroh, the tickets, the hash lists and the origin
  are untouched.

## What it does not do

As in 0.1.0: **no public network** (run your own scoped relay and iroh relay), **no payments**,
**Linux x64 binaries only**, not signed by an operating-system vendor, and the Hypercore profile
(NFX-12) is not implemented in Rust. `nfxd fetch` throughput is open (issue #21).

## Verify

`sha256sum -c SHA256SUMS` checks that the tarball is intact; it does not say who made it. For that,
the release carries `release-event.json`: a Nostr release notice (kind 30071, `d` = `nfx`) signed
by the SovTech key `npub1s0vtechh66tx7vrwdud8zfyheu9zca7swwfrzd4qu2a4f93mxs6qvn9adx`, listing the
tarball's sha256 and size; the same notice is on Nostr relays. To check it, with Node 22.18 or
newer and a checkout of nutflix-pear (whose release scripts sign and verify both projects'
notices):

```sh
git clone https://github.com/SovereignTechnology/nutflix-pear.git && cd nutflix-pear
npm ci --ignore-scripts
node scripts/release-verify.mjs release-event.json --d nfx nfx-0.1.1-linux-x64.tar.gz
```

It checks the signature, that the key is SovTech's, that the notice is NFX's, and the file's size
and sha256. The release is built by `.github/workflows/release.yml` from the tagged commit in the
pinned `rust:1.98.0-bookworm` image, `--locked`, with the commit's timestamp and the build paths
remapped.
