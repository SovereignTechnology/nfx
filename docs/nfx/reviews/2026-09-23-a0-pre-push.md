## Adversarial pass on verification (nfx-proto)

| Attack | Result |
|---|---|
| Parse one thing, sign another (events) | `Event::verify` recomputes the id from the same struct the parser reads, and serde's derive rejects duplicate top-level fields. Tags are read from the verified struct. |
| Parse one thing, sign another (voucher, gossip) | The signature covers `canon` of the *received* value, and the fields are read from that same parsed value. Duplicate keys, floats, `-0` and lone surrogates are rejected before hashing (`canon.json`). |
| Cross-network replay | Exactly one `n`; `d`/`a` must carry the same namespace; the gossip beacon must match the topic's video. Vectors: `n-d-mismatch`, `two-n-tags`, `a-namespace-mismatch`, gossip "foreign swarm". |
| Poisoned bytes | `HashList::verify` hashes before parsing; `verify_file` enforces the Blossom rule; playlists may only reference listed content names. |
| Panics on hostile input | Index accesses are guarded (`single_tag` rejects value-less tags; `tag_values` filters empty tags). The `expect`s are only on serializing owned strings and integers. `serde_json`'s recursion limit bounds the canon parser. |
| Integer tricks | Strict decimal grammar, `checked_sub` on TTL, `abs_diff` on clock skew, `u64`/`u16` conversions checked. |

## Sharp edges found and fixed before commit

| # | Where | Edge | Fix |
|---|---|---|---|
| F1 | `voucher.rs` | Two-step API (`verify` + `check_against`): a mint that forgot the second call would release keys for any voucher the creator ever signed, for any video. | One public entry point, `Voucher::verify(wire, sig, &manifest, now)`, taking the signer from `manifest.author` and always checking video, licence and `free_seeder`. The lower-level functions are private. |
| F2 | `hashlist.rs`, `beacon.rs` | Callers had to pass the right manifest fields by hand. | Added `HashList::verify_for(&Manifest)` and `Beacon::serves(&Manifest)`. |
| F3 | `hex32::is_https_url`, NFX-02 §4 | `https://mint.example@evil.example` passed as an https URL. | Userinfo rejected. Stated in NFX-02 §4, and a new vector `mint-userinfo`. |
| F4 | NFX-10 §3.2 (my amendment 5 draft) | "A chunk counts from its first byte": an uploader could send one byte each of 8 chunks and be owed 8 chunks. | A chunk counts only when complete and sha256-verified; aborted transfers count for nothing. |
| F5 | `beacon-invalid.json` | The `video-mismatch` case was rejected by the infohash check, not the check it names. | The case recomputes the infohash, so the rejection reason is now the video/`a` mismatch. |

## Remaining risks (not blockers for pushing a Draft spec)

- The M2/M3 open issues recorded in NFX-07 §7, NFX-08 §7 and NFX-09 §6: bare-`root` mint
  state, the unauthenticated voucher path, `accepts_mints` meaning "any", fees, and
  mint-chosen seeder secrets. They gate those freezes.
- `Event::sign` and `sign_digest` sign deterministically with raw keys. That is fine
  for vectors and testnet. Real user keys belong in a signer (nostr-sdk / NIP-46).
- The P2PK lock (NFX-08 §4) creates a refund race after `locktime`. It is bounded by
  the 3600 s minimum and by redeem-before-locktime seeder duty; revisit with real
  CDK timings at M3.
- CI is dormant (no runner). Every result above is a local run.

## Coverage

12 test groups over 11 vector files, run natively and on `wasm32` (Node). Every
invalid vector is rejected, and a diagnostic run confirmed each rejection names the
rule its case was built for (33 manifests, 11 beacons, 9 hash lists, 2 playlists,
7 canon rejects). The carry rule was property-tested in Python over 20 000 random
redemption sequences; it lives in spec text only, and there is no mint code yet.

Verdict: **no blocker.** Push is subject to sovtech's OK.
