# Second independent audit: M2.0 rework (`92ccc44`, 2026-09-24)

- **Auditor:** a fresh agent, with no author review to read.
- **Scope:** `81a692e..92ccc44`, branch `m2/contracts`. That is M2.0 plus the rework that
  answered the first audit
  ([`2026-09-24-m2.0-independent-audit.md`](2026-09-24-m2.0-independent-audit.md)).
- **Method:** `git archive 92ccc44` into scratch, then:
  - 22 new mutants in the mock;
  - exploit tests measuring the impact of each surviving mutant, and of the honest design;
  - 141 parser probes against an independent reading of NFX-07 §2;
  - the lock, `check.sh` and the CI file, read line by line.
- **Controls:** the honest mock still passed 25/25 with the auditor's additions in
  place, and every one of the 27 planted flaws was still caught.
- **Limits (stated by the auditor):** the lock finding (H6) comes from reading only. A
  safety classifier stopped the bypass runs in the clone.
- **Verdict: not complete for push.**
  - Seven plausible defects passed all 25 scenarios, with measured impact. One served
    404 chunks for 200 sat; others served 200 or 110 unpaid chunks against a global cap
    of 10.
  - The honest design failed two of its own claims when run:
    - the global cap became a permanent denial of service;
    - the bounds and bans held per video, not per seeder.
  - An honest viewer could not resume after a reconnect.
  - The lock still left the money code's build and test inputs unpinned.

The resolutions are in the commit that follows this record. The auditor's mutants are
kept as planted flaws, and their exploits as scenarios.

**H6 in detail:**
- The pins cover:
  - all of `crates/nfx-pay`, including the mock;
  - the parser's modules;
  - the workspace manifest's `profile`, `patch`, `replace` and lints sections;
  - the check's helper `crates/ci/locked.py`;
  - nfx-pay's resolved dependency closure (in `locked-compiled.txt`).
- Tracked Cargo configuration or toolchain files are refused. So is a Cargo config in
  `CARGO_HOME` under CI.
- `--compiled` checks three things:
  - every source file the compiler read for nfx-pay is a pinned one, and nothing
    compiled into nfx-node comes from outside nfx-node;
  - only pinned workspace crates may depend on nfx-pay, and only locked paths in
    nfx-node may name it;
  - build scripts and proc-macros in the workspace are limited to a pinned list.
- **Stated limits:**
  - A committer who can push can still re-pin.
  - The CI configuration lives in the branch it checks. Moving it out of the branch is a
    GitLab setting and sovtech's call.
  - Money logic written without naming `nfx_pay` cannot be recognised mechanically.
  - Unpinned code that CI runs between the two checks could alter files and restore
    them. That code's own diff is where it would show.
  - `.gitlab/CODEOWNERS` is a mirrored demo file, so it is not edited here. Code-owner
    approval is a GitLab setting and sovtech's call.
  - The CI cache is keyed per branch.

## The rework, verified (author, before the third audit)

- **Suite:** 35 scenarios pass against the honest mock.
- **Teeth:** 61 planted defects are each caught (`tests/mutants.rs`): every mutant from
  both audits, plus two found while writing, a paid chunk kept in the cap and a viewer
  that stops on an outage. Writing them also exposed two weak scenarios, which were
  fixed:
  - the debt-ageing scenario asserted in an order where the cap hid the flaw;
  - the honest pair answered payments instantly, so paying at the full window never
    stalled. Answers now arrive one request late.
- **Parser:**
  - `pay1.json` holds 18 valid lines, 3 loopback-only and 66 invalid. The generator's
    reference reader agrees with every verdict in both modes.
  - The Rust reader agrees with it on 4,141 cases: this audit's 141 probes (quotes
    given the new fields) and 4,000 lines fuzzed from the valid vectors. It accepts 460
    of them, and every accepted message survives its own writer.
- **Lock:** 23 bypass attempts were each refused. The four only the compiled stage can
  see were re-run to confirm each fails for its intended reason:
  - a multi-line `#[path]` smuggling an untracked file into nfx-node (dep-info);
  - `nfx_pay` named in nfx-node's `lib.rs` (the name check);
  - a new build script in nfx-media (the pins);
  - nfx-media depending on nfx-pay with `Cargo.lock` updated (the pins).

  After each run the check read clean again.
- **CI:** `crates/ci/check.sh` passes in full.
