# Review: the desktop viewer and `Daemon::watch` (2026-09-24)

Scope:
- `crates/desktop`: `main.rs`, `ui/`, `tauri.conf.json`, `deny.toml`, `e2e.sh` and
  `run.sh`;
- `nfxd::daemon`: `internal_origin`, `Daemon::origin` and `Daemon::watch`, with the
  runtime task list.

Method: `differential-review` (a new local trust boundary: the webview and IPC) and
`sharp-edges`.

| Concern | Result |
|---|---|
| The webview playing unverified bytes | Media comes only from `nfx://`, served by the daemon's origin. That origin re-hashes on every read, serves only files of manifest-verified hash lists, and pulls misses through the bounded, re-anchoring fetch. Tested end to end. |
| Script injection into the page | The CSP allows only `'self'` scripts, with no inline script (the page script is `app.js`). The DOM is built with `textContent` only. Nothing remote is loaded. |
| IPC misuse | Every command is the app's own. `watch` parses the address with `nfx-proto`, and `save_settings` accepts only `ws://`/`wss://` relays and valid iroh relay URLs. Only the local page can invoke them. |
| The node key | Created with `create_new` and mode 0600 in the app data dir, then loaded with the mode check. Only the public key reaches the page. |
| A stalled or absent seeder | `watch` times out after 150 s with a message. Pulls use the source cooldowns and deadlines from the pre-push audit. |
| Settings restart | The old node is shut down before the new one starts (no double bind), and settings are written only after a successful start. |
| Test mode | Active only with `NFX_DESKTOP_TEST`, and a watchdog exits after 240 s. The e2e runs in a private headless compositor, keeps its keys in a 0700 temp dir that it removes, and kills only its own sessions. |
| Supply chain | `cargo deny` passes with the desktop policy: named MPL-2.0 exceptions for Servo's CSS parsers and `option-ext`, and five `unic-*` "unmaintained" notices ignored by ID with reasons. No vulnerability advisories. |

Carried forward:
- **The first play can wait up to 60 s** when no beacon is in flight, because beacons
  are ephemeral (NFX-03 §5). Gossip or an origin hint would shorten this. Wiring gossip
  into `nfxd` is on the list.
- **Linux only**, as in S2. macOS and Windows webviews are untested.
- **The desktop workspace is not in CI.** It is checked locally with clippy, deny and
  the e2e.

Verdict: **no blocker.**
