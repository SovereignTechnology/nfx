**The seeder.** The honest mock caches keys per mint and per keyset, and checks each proof
against the keys of the keyset it names (NFX-07 §3 step 3 now says so); the suite holds
keys only by making an engine fetch again, so an honest caching engine passes it. A payment
whose turn comes in its deadline's second runs no check, structure's included. A payment
that waited for the turn and took it, then was dropped or refused, frees and wakes as any
other and sets the reads' floor. A hello's ban recheck ages the bans on every path.

**The watcher.** A quote or `ack` on another video settles nothing of this video's payment,
refused, second, dishonest or taken, and a stop by one still reclaims. A live payment's
180 s count from sending, whatever comes on the session; a stopped watcher claims nothing
back before them. Only a `mint-unavailable` answer to a payment uses a try, and only an
`ack` or a new session's accepted quote restores them. After any code but
`mint-unavailable` the watcher stops, for every code the wire knows and an unknown one; a
refused `hello` changes nothing, `mint-unavailable` included. NFX-07 §3a and `Viewer::due`
say the watcher pays once half the window is unpaid, rounded up, as the suite required.

**§4, origins.** Only a `200` whose body verifies as the requested file serves a paid
request; one that does not verify stops payments to that origin. Every other refusal with
nothing spent uses one of three tries; out of tries, the client backs off (never zero, at
least doubling) and then has three again, so an honest origin is never dropped for good. The
client pays only within its price cap and only mints the origin names, keeps one standing
per origin, and sends a paid request for the whole file over HTTPS, following no redirect.
The origin SHOULD hold the file before it swaps, answer within 60 s, and keep the
connection open for the whole `200`. A stated concession: a payment an honest origin's swap
took is lost when the client does not get the `200` whole within its wait.

**How the suite waits (#20).** It judges progress by the answers an engine awaits and by
the engine settling, never by a count of polls. Its helpers poll with the task's waker and
yield to the runtime; they wait in real time while the harness reports an answer under way,
and take a future as waiting only after 100 quiet runtime turns, so a still-waiting check
settles before it asserts. A third harness answers the mint's reads from another thread
2 ms after they are sent, and all 63 scenarios pass on it (`tests/woken_reads.rs`, counted by
the lock). The `Harness` contract says what the suite assumes of an engine's progress. The
hunt pinned the wakes an entry needs from the clock: the next second, the second's end, a
read coming back, a dead turn's deadline, for payments as for hellos.

## The rework, verified (author, before the twenty-ninth audit)

- **Suite:** 63 scenarios pass against the honest mock on three harnesses: synchronous
  reads, reads as round trips, and reads answered from another thread.
- **Teeth:** 982 planted defects each fail a named check of the suite in `adversary.rs`,
  200 entries new: 102 new flaws (46 on both seeder harnesses, 5 on round trips only, 51 of
  the viewer) and 52 earlier round-trip-only flaws now registered on the synchronous harness
  too. None is caught by hanging, a runtime panic or a panic elsewhere.
- **Where each is caught:** of the 782 earlier entries, 776 fail at the same check with the
  same message. One prints its compared values differently at the same check; five
  round-trip entries now fail at a still-waiting check that settles before it asserts, each
  at its own behaviour. Merging the groups moved nothing.
- **Runner:** `tests/runner.rs` 9/9.
- **CI:** GitHub Actions passes the lock and the checks at `e363fc2` (adversary 63,
  round_trip 63, woken_reads 63, mutants 982, runner 9, pay1 2). The lock was re-pinned after
  the groups' merge and again after group d; the compiled facts did not change. The first
  run on GitHub also found the vector generator failing on Python 3.11 (the 2000-level
  nesting vectors); it raises the recursion limit now (`8a5ccac`).
- **Left open:** two defect modes, an outcome or a key answer landing without waking the
  payment, fail only by hanging, which the runner's timeout counts but no named check does;
  the contract assumes an engine awaits its own calls, which an actor-style engine does not;
  the woken harness answers reads and the sweep from another thread, not swaps or key
  requests.
