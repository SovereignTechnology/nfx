# Pre-push review: ADR 0100 (branch `spec/creator-managed`, 2026-09-25)

- **Scope:** two documentation files, `docs/decisions/0100-creator-managed-mode.md` and
  `docs/nfx/status.md`. No code, no vectors, no spec text yet.
- **Method:** `sharp-edges` on the keyholder license call, the certificate, the `hello`
  binding and the retainer contract, treating the ADR as the API it will become;
  `differential-review` reduced to what a docs diff can carry: no secrets, no live
  paths, no claim about a frozen document that the frozen text contradicts.
- **Verdict:** four design gaps, all fixed in the ADR before this push. Nothing in the
  diff leaks anything.

| # | Sev | Finding | Resolution |
|---|---|---|---|
| 1 | High | **A hosted keyholder needed the creator's identity key** to sign certificates, so "hosted" meant handing over the Nostr identity. | New manifest tag `cert_key`, a delegated pubkey the keyholder holds; certificates verify against it, never against the creator's identity key. |
| 2 | High | **A certificate alone was bearer.** A captured `hello` could be replayed to any seeder for any session. | `hello` carries a signature by `W` over `(a, session, seeder transport id)`; `not_after` is required and 0/absent is invalid; verifiers check the `type` domain separator against vouchers. |
| 3 | Med | **Challenges were unbounded**: `length` 0 passed trivially, and an unsigned challenge let anyone make a seeder serve on demand. | Creator-signed challenges, `length` 1–64 KiB, in-file range, one per file per period, drawn only from what the ask claims. |
| 4 | Med | **Rules the split design had were silently dropped**: exact-amount license payment, idempotent retry after a dropped response, the mint URL grammar for `keyholder`/`pay_mints`. | Restated as mandatory in §1, with `key_price` 0 defined (registration wall) and `rate` ≥ 1 for asks. Payouts bound to the transport identity the signed beacon named. |

Checked and found sound: `mode` absent defaults to the mode in which the creator's
income path is identical (safe default); the claim that `mode`, `keyholder`,
`pay_mints`, `cert_key` and `ask` need no `specver` bump (NFX-02 §3 and
`beacon-content.schema.json` `additionalProperties: true` say unknown fields are
ignored); `split`/`cashu_key` stay required by frozen NFX-02 §4 and are carried.

Left for the spec text (NFX-08 rewrite, NFX-13): the `nfx/bill/1` message set and its
rate limits, the assignment's `term` ceiling, and what a keyholder does when a
watcher's mint is unreachable (`503`, then the NFX-07 §4 reclaim rule).
