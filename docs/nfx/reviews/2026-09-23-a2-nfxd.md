# Pre-push review: A2 `nfxd` (`a2/nfx-node`, 2026-09-23)

Scope:
- the new `crates/nfxd` crate: `key`, `package`, `daemon`, the CLI, and
  `tests/daemon.rs`;
- in `nfx-node`, `SwarmPull::fetch_video`.

Method: `sharp-edges` (the CLI and key handling) and `differential-review` (the daemon
wiring). Every protocol check it relies on is reviewed in the `nfx-node` layer reviews.

## Adversarial pass

| Concern | Result |
|---|---|
| The secret key leaking | Key files are created with `create_new` and mode 0600, so an existing key is never overwritten. `load` refuses group- or world-readable files, and the error names the mode, never the contents. Tested, including that the error does not contain the secret. The CLI prints public keys only (hex and npub). |
| Publishing a manifest that does not match the bytes | `Package::open` verifies the hash list in the store against `nfx.json`'s root, video and segs, and `sign_manifest` parses its output back. Tested: a mismatched `nfx.json` is refused. |
| A fetcher trusting a relay or a seeder | Manifests go through `Relays::manifests` (NFX-02 plus the query re-check), and beacons through `BeaconWatch` (NFX-03). Bytes go through `Node::fetch` (sha256 re-anchor), and a lying source is forgotten. The daemon adds no trust path of its own, and never learns from its own beacons. |
| Seeding what is not there | `Node::seed` verifies every file before importing. The origin holds only verified lists. |
| Flags that conflict | `--seed` and `--fetch` need `--key`; `--pull` needs `--origin`; a repeated single-valued flag is an error; an unknown flag gives the usage text (exit 2). |
| A relay down at start | Manifest resolution retries on errors as on absence, and the state stays `Resolving`, visible on stderr. |

## Sharp edges carried forward

- **Binding.** `--origin` and `--embed-relay` bind exactly what they are given. On a
  public address the relay should self-announce (NFX-04 §6, not implemented), and both
  want TLS in front. Document this in the operator runbook when `nfxd` is deployed.
- **Gossip is not wired in.** The daemon uses Nostr beacons only. Joining the video's
  gossip swarm (NFX-06 §4) is a later step, and the envelope signing needs the raw
  secret, which `Keys` would have to hand over.
- **The iroh identity is fresh at every start**, so tickets change across restarts.
  Harmless, since beacons republish every 60 s, but a persistent iroh key is an option.
- **A fetch retries forever** every 2 s against live sources. An unreachable source can
  hold one attempt for up to 120 s (`FETCH_TIMEOUT`).

Verdict: **no blocker.** The push waits for sovtech's OK.
