# Ninth independent audit: M2.0 (`18d30a8`, 2026-09-25)

- **Auditor:** a fresh agent, with no author review to read.
- **Scope:** `81a692e..18d30a8`, branch `m2/contracts`. The eighth rework was examined
  hardest.
- **Method:**
  - 15 new mutants of the mock: 1 caught, 12 surviving with measured impact, 2
    equivalent. Each surviving mutant has a paired test that passes against the honest
    mock and fails under the mutant;
  - a Rust probe against `pay1.py` over 244,149 cases, each in both loopback modes. There
    were 0 disagreements, and the writer never refused a line the reader accepted;
  - lock routes in a disposable clone, run through the lock job's steps under `env -i`
    in CI mode.
- **Controls:** 62/62 scenarios, 181/181 planted flaws and pay1 2/2 on the pristine tree;
  the CI lock job passed on a pristine clone.
- **sovtech's bar:** zero findings.
- **Verdict:** not complete for push. 12 findings: 1 High, 3 Medium, 6 Low and 2 Info. All
  eight resolutions of the eighth audit held.
- **Not findings:**
  - the designed trade-offs NFX-07 and the lock's header state;
  - two equivalent mutants. One checks the amount before the DLEQ: both orders refuse,
    and only the code differs for a token that is both mis-valued and DLEQ-invalid. The
    other bounds the due amount by `u64` alone: that differs only for one token worth
    more than 21 M BTC.

The resolutions are in `fd79665`.

**The High finding, and the crate.** Inside one crate, an unpinned module can change how a
pinned one compiles, and nothing a lock reads from the build can show it. The auditor ran
two routes:
- a `#![macro_use]` module declared before `pay`, whose `matches!` then shadowed the
  standard one in the pinned parser, which began to accept malformed tokens;
- an inherent `clone` on `Quote`, which beats the derived `Clone` for every caller,
  pinned `nfx-pay` code included.

Both passed every mode of the lock. The seventh audit's premise, that what other code
compiles of a pinned file "is still that file, unchanged", does not hold within a crate.
So the pay/1 wire, and the modules it rests on (`canon`, `namespace`, `hex32`, `error`,
`sha256`), moved into a crate of their own, `nfx-pay-wire`:
- `nfx-proto` re-exports it unchanged, so no caller changes;
- `nfx-pay` depends on it alone;
- the lock pins both money crates whole, every tracked file and no untracked one;
- `locked.py` fails if either depends on any other workspace crate.

A crate boundary blocks both routes. A macro cannot reach into a crate that does not
import it, and an inherent `impl` on another crate's type does not compile (E0116). Pinning
all of `nfx-proto` instead would have closed the hole too, but it would have put every
future change to beacons, manifests and gossip behind the security stage.

## The rework, verified (author, before the tenth audit)

- **Suite:** 62 scenarios pass against the honest mock; none were dropped.
- **Teeth:** 196 planted defects are each caught. Each of the 15 new ones fails the
  assertion written for it.
- **Lock:** each route was run on the committed tree:
  - **Route A** (a `#![macro_use]` module with its own `matches!` in `nfx-proto`):
    nfx-pay-wire's files are untouched and its pay/1 vectors pass. The macro reaches only
    `nfx-proto`, whose own `matches!` calls it breaks.
  - **Route B** (an inherent `clone` on `pay::Quote` from `nfx-proto`): does not compile
    (E0116).
  - **The money crates themselves:**
    - an untracked file in `nfx-pay-wire` is refused;
    - a new tracked module in it is refused by the pins;
    - `nfx-pay` depending on `nfx-proto` is refused by the pins, and, run directly with
      the lock file updated, by the facts ("a money crate depends on nfx-proto, a
      workspace crate not locked whole").
  - **The CI-mode sources step:** a `CARGO_HOME` outside the checkout is refused, with
    its extracted sources untouched; the job's own, inside the checkout, is cleared.
  - The pristine tree passes again.
- **CI:** `crates/ci/check.sh` passes in full. It ran adversary 62, mutants 196 and pay1
  2, and the pay/1 vectors under wasm32 in their new crate. The lock reads 80 metadata
  facts; 112 are pinned with the money build's.
