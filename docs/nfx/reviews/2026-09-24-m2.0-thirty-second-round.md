- *D1, the half-window credit bound (the thirtieth round's row 12).* Three decisions in one:
  one request unanswered at a time for a seeder and a video; after a refusal, the `due` it
  licenses before the next request; and "answered" as the whole file arrived with its
  sha256, the seeder's refusal, or the watcher's abandonment, which stays owed.
  - *The spec* (`c8ec101`). NFX-07 §3a gains the bullet "Keep one request unanswered at a
    time": under one identity toward the seeder, across every session with it for the
    video; part of a file (its first byte included), a payment, its answer, a timeout and
    the session's end answer nothing; requests to several seeders, or for several videos,
    go at once; a duty of the watcher, which a seeder states no rule of. The licence's
    sentence says the licensed decision comes before the next request, whether or not it
    pays, and no longer names a request among what comes between. The bound now says how
    it holds: "With one request unanswered at a time and that decision made before the
    next, credit on a video never grows beyond half its window, rounded down." The lists of
    what frees no place, of what a live payment's 180 s run through, and of what undoes no
    stop name a request answered beside one sent. §3's admission says that a watcher keeps
    one request unanswered for a video, and that the seeder's atomic count of concurrent
    requests (`concurrent_admission_is_atomic`) stays, bounding a peer that does not.
    NFX-10 §3 and §3.2 say that a page keeps both rules, its loaders fetching from several
    seeders at once and from each one file of a video at a time. Each spec has its
    changelog entry.
  - *The locked crate* (`deadc36`). `Viewer::requested` returns `Result<(), Unsent>`: a
    request held back is not sent and changes nothing, `Unsent::Unanswered` while one of

    while a refusal licenses a `due` not yet made. Two inputs are new:
    `served(Served::Part | Served::Whole)`, of which only the whole file answers; and
    `abandoned()`, which answers and leaves the request owed. `refused` answers the request
    unanswered; with none it is no answer and licenses nothing. `end` leaves a request
    unanswered as it is. The trait has 15 methods where it had 13. The honest mock keeps
    an unanswered count and a `due` owed first per ledger, apart from its licence flag, so
    that no older planted defect of the licence changes what it does.
  - *The suite* (`467d7b1`). A new scenario, `a_viewer_sends_one_request_at_a_time`.
    `a_refusing_seeder_takes_at_most_half_a_window` runs on a window of 5, asks for a second
    request while the first is unanswered and for a third between the refusal and its
    `due`, the seeder refusing whatever is sent after that `due` would have paid for it,
    and asserts 2 chunks, rounded down. Of the 347 calls of `requested()` the suite made, those
    a test meant answered by the file are now requests sent and served whole

    answered later, or left unanswered where that is the point). The shared tables take two inputs more (a request served
    whole, one abandoned), one refusal licensing at most, and in half their cells a request

    input was. Their pinned counts were taken again from the honest runs.

**Decisions taken in making the round:**
- *The answer is two inputs, not one.* `served` says what arrived of the file, and
  `abandoned` that the watcher gave the request up: a part of a file is an input, which an
  honest watcher takes as no answer, so that a watcher that takes it for one can be caught.
- *A request held back is a typed refusal, not a panic and not the caller's duty:* the
  watcher is the one the rule binds, and the suite can see it hold one back.
- *The order rule has its own flag in the mock,* beside the licence: an older defect that
  keeps or ends the licence wrongly still does only that.
- *The tables answer an unanswered request before they send the next* (`World::request`),
  and check after every input that one left unanswered is still held back.
- *A key request or a listing at a mint that is down fails at once*, as a swap there does,
  rather than waiting for the payment's deadline; the listing's failed ask counts as that
  second's.
- *A read is split by the mint of its swaps' tokens.* One request across two mints is the
  defect `OneMintsOutageTakenForAll`, which is how the honest mock read before this round.

**Awaiting sovtech's decision.** Eight points of the round's own making, each written into
the text or the code as it stands, which sovtech has not yet read:
- *Of D1:*
  - A `refuse` that comes after the watcher abandoned its request is no answer, and the
    request stays owed. NFX-07 §3a says so; in that edge it overrides "a refused request is
    always un-owed".
  - `refused`, `served` and `abandoned` with no request unanswered change nothing.
  - `Served::Part` is an input that an honest watcher ignores: it is there so that the
    suite can test what counts as an answer.
  - CI's time: `honest_timings` took 2,372 s for 3,301 tests (run 40220423952), where the
    thirtieth record had 1,230 s for 2,223; the check job's limit is 180 min.
- *Of D3:*
  - Keys and a listing at a mint that is down fail at once, `mint-unavailable` at once, and
    the listing's failed ask counts as that second's (NFX-07 §3 step 3's new sentences).
  - The whole outage (`mint_outage`) in the mock still serves keys and listings, as before
    this round; only an outage of one mint takes them. Changing that would move scenarios
    that stand.
  - `restore_outage`, `state_check_outage` and `MintEvent` have no form of one mint.
  - `mint_outage(false)` brings back every mint, those down alone included.
